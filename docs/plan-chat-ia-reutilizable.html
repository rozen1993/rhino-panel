Chat IA reutilizable

Un asistente de consulta, exclusivo de Admin y de solo lectura, desacoplado de Sistema R para poder integrarse después en otros productos.

Decisión central: Hermes no será el backend del producto. Puede vivir en el VPS como agente personal y laboratorio. El componente compartido usará un gateway pequeño, auditable y sin estado.

Responsabilidades

  • Widget: recibe una URL y un token corto; renderiza conversación, fuentes y estados. Nunca conoce claves de proveedor.
  • Gateway: valida al Admin, limita uso, arma el prompt, registra métricas y llama a OpenRouter.
  • Conector del producto: obtiene contexto usando la identidad real del usuario. Nunca usa service_role para saltar permisos.
  • Proveedor: OpenRouter queda intercambiable detrás de una interfaz; una lista blanca evita modelos inesperados.

Contrato reutilizable mínimo

POST /v1/chat recibe mensajes, identificador de proyecto y token corto. Devuelve texto por streaming, fuentes consultadas, modelo, consumo estimado y un identificador de trazabilidad.

Uso de los USD 10

  1. Definir 20–30 preguntas reales con respuesta esperada.
  2. Probar dos modelos económicos y uno de referencia.
  3. Medir precisión, latencia y coste por conversación.
  4. Elegir por evidencia y fijar un presupuesto mensual antes de abrir uso continuo.

¿VPS o función serverless?

Comenzar serverless si el producto solo necesita chat: elimina parches, TLS y disponibilidad de un servidor propio. Usar el VPS de Hostinger para Hermes o para cargas persistentes únicamente cuando exista una necesidad medida.

Hermes: agente personal single-tenant de Marco, útil para experimentar con herramientas y automatizaciones. No comparte memoria, credenciales ni disponibilidad con el widget reutilizable.

Stack sugerido

  • TypeScript; gateway en una función serverless compatible con streaming.
  • Interfaz de proveedor propia sobre OpenRouter para cambiar de modelo sin tocar el widget.
  • PostgreSQL opcional para conversaciones y métricas; retención desactivable por proyecto.
  • Pruebas de contrato, aislamiento, accesibilidad, presupuesto y evaluación de respuestas.

Definition of done de la primera versión

  • Solo un Admin autenticado puede abrirla.
  • No existe ninguna operación que escriba en el producto.
  • La clave del proveedor no aparece en navegador, repositorio ni logs.
  • Topes de gasto y modelos permitidos fallan cerrados.
  • Cada respuesta distingue evidencia, inferencia y ausencia de datos.
  • El widget puede integrarse en un segundo proyecto cambiando configuración, no código central.
