La decisión principal

Primero se completa y valida la plataforma funcional. En el presente inmediato, OneDrive es solamente un enlace externo que debe guardarse, mostrarse y abrirse correctamente. La organización avanzada, los permisos internos de Microsoft y Microsoft Graph pertenecen a una segunda fase posible, no al alcance actual.

Claude y Codex analizaron de manera independiente el estado del repositorio, las pruebas y los contratos vigentes. Ambos llegaron al mismo orden de trabajo. No hubo contradicciones sustantivas; únicamente Codex detalló más la forma incremental de implementar el futuro backend.

Fase actual

OneDrive ahora: un enlace funcional

En la versión actual, la plataforma no administra archivos ni carpetas de Microsoft. El material permanece fuera de Sistema R. Solo se registra la dirección que permite abrirlo.

Contrato inmediato del enlace

  1. El operario pega una dirección HTTPS de OneDrive o SharePoint.
  2. La plataforma valida que el formato y el dominio sean admitidos.
  3. El enlace se guarda junto a la actividad y sobrevive a recargas.
  4. Solo se muestra a los roles autorizados por el contrato vigente.
  5. Se abre en una pestaña nueva sin modificar el contenido.
  6. Antes de dar por válida la entrega, una persona comprueba que el enlace abre y que su cuenta tiene acceso.
Límite importante: comprobar el formato y abrir el enlace no garantiza que Microsoft mantenga el archivo disponible para siempre. Si el propietario elimina el archivo, cambia los permisos o el enlace caduca, Sistema R no puede repararlo automáticamente en esta fase.

Fuera del alcance inmediato

  • Subir fotografías, videos o documentos desde Sistema R.
  • Crear carpetas automáticamente.
  • Leer el contenido del material o descargarlo.
  • Administrar permisos internos de Microsoft 365.
  • Conectarse con Microsoft Graph.
  • Validar automáticamente que cada destinatario pueda abrir el enlace.

Aceptación manual antes de avanzar

El paso siguiente acordado es comprobar la plataforma en dispositivos reales. La prueba debe cubrir:

  • Ingreso y cierre de sesión de Operario, Admin y Burson.
  • Creación, edición, recarga y entrega de una actividad.
  • Persistencia y apertura del enlace OneDrive.
  • Encargo Burson y asignación al operario especial.
  • Conversación Admin–Operario y bloqueo posterior del enlace y la opinión.
  • Histórico en móvil, tablet, laptop y PC.
  • Ausencia de acceso a información de otros roles.

Criterio para avanzar: no queda ningún defecto que impida completar un flujo, pierda información, exponga datos a un rol incorrecto o vuelva inutilizable una pantalla.

Segunda fase posible

OneDrive avanzado, cuando sea necesario

Marco no descarta una integración futura. Cuando la operación real demuestre que manejar enlaces manualmente genera errores o trabajo repetitivo, se podrá evaluar una segunda fase. Esta fase debe decidirse por necesidad comprobada y no construirse por anticipación.

1. Organización de carpetas

Definir si existe una biblioteca corporativa, una carpeta por año, cliente o actividad; quién es propietario; cómo se nombran las carpetas; y cuánto tiempo se conserva el material.

2. Permisos internos

Definir qué usuarios o grupos de Microsoft 365 pueden leer, editar o compartir; si se permiten invitados; si los enlaces caducan; y qué ocurre cuando una persona deja el equipo.

3. Microsoft Graph

Evaluar una conexión mediante la API oficial de Microsoft para crear carpetas, generar enlaces, consultar metadatos o verificar permisos. Esto exigiría registrar una aplicación, gestionar credenciales, solicitar permisos mínimos, manejar consentimiento y registrar auditoría.

4. Ciclo de vida del enlace

Definir cómo detectar enlaces revocados, archivos eliminados o permisos cambiados; quién recibe la alerta; y cómo se reemplaza un enlace sin perder trazabilidad.

5. Seguridad y operación

Evitar guardar secretos en el navegador, mantener credenciales en servidor, aplicar mínimo privilegio, registrar accesos relevantes, preparar recuperación ante fallos y establecer soporte.

Señales que justificarían esta segunda fase

  • Muchos enlaces rotos o inaccesibles.
  • Errores frecuentes al compartir permisos.
  • Volumen de actividades que vuelve lenta la organización manual.
  • Necesidad de auditoría corporativa sobre archivos y accesos.
  • Necesidad de automatizar carpetas o verificar disponibilidad.
Decisión conservada: esta integración futura es posible, pero no está aprobada ni es necesaria para considerar funcional la plataforma actual.

Arquitectura productiva posterior

Después de aprobar el frontend, Claude y Codex recomiendan documentar antes de implementar:

  • Hosting y ambientes de desarrollo, prueba y producción.
  • Identidad, inicio de sesión y recuperación de acceso.
  • Matriz de autorización de servidor para los tres roles.
  • Base de datos, auditoría persistente y respaldos.
  • Migración de los adaptadores actuales de navegador.
  • Tratamiento del enlace OneDrive como texto seguro en la primera versión.

El primer corte vertical recomendado comprende autenticación real, administración de cuentas y una actividad completa. Solo después de probar ese recorrido se migra el resto.

Migrar Histórico, Burson, conversaciones y auditoría; preparar operación y despliegue.

Salida: plataforma productiva estabilizada.

Etapa 5 · Evoluciones opcionales

Evaluar, por separado, Microsoft Graph y el asistente IA. Cada uno requiere su propia decisión de alcance, seguridad y costo.

Entrada: datos confiables, permisos reales y necesidad demostrada.

Riesgos identificados por ambos agentes

  • Confundir un prototipo funcional con un producto seguro para producción.
  • Diseñar la base de datos antes de congelar campos y flujos.
  • Intentar migrar todo el sistema en un único cambio.
  • Iniciar IA o Microsoft Graph sin datos, permisos y operación estables.
  • No definir fecha, entorno, responsables y criterio de lanzamiento.
